## 2. 二期定位

一期已经解决了“单次导购”的主链路：提问、追问、推荐、对比、反馈、会话管理。

二期要解决的是“持续购物决策”：

1. 用户不是只问一次，而是会反复回来比价、看提醒、看偏好。
2. 用户希望系统记住自己喜欢什么、避开什么、预算怎么变。
3. 用户希望系统在合适的时候提醒，而不是每次都重新输入完整需求。

一句话定位：

> 从“帮用户选一次”升级为“帮用户持续做购物决策”。

## 3. 二期业务场景

### 3.1 偏好记忆

用户多次咨询空气炸锅、咖啡机、收纳等商品后，希望系统记住：

1. 预算区间。
2. 品牌偏好。
3. 对噪音、容量、易清洗的偏好。
4. 已明确排除的条件。

### 3.2 价格关注

用户看到心仪商品后，不一定马上买，希望先关注并在降价时收到提醒。

### 3.3 复访决策

用户下次回来时，希望直接看到：

1. 上次推荐结论。
2. 上次未决问题。
3. 继续追问入口。
4. 关注商品是否有价格变化。

### 3.4 搭配购买

用户买单件商品后，还想知道：

1. 是否需要搭配配件。
2. 是否有更适合的补充购。
3. 是否有同场景的组合方案。

## 4. 二期目标

### 4.1 用户目标

1. 少重复输入。
2. 少重复解释偏好。
3. 关注的商品有变化时能及时知道。
4. 回访后能快速回到上次的决策状态。

### 4.2 业务目标

1. 提升回访率和复购相关点击率。
2. 提升关注-提醒-回访链路转化。
3. 降低用户重复提问成本。
4. 提升导购助手的长期使用感。

### 4.3 产品原则

1. 不打扰优先，提醒要克制。
2. 偏好可控，用户能看、能改、能删。
3. 推荐可解释，持续能力不能牺牲透明度。
4. 桌面 Web 优先，本期不做移动端。

## 6. 不做范围

1. 移动端适配。
2. 自动下单。
3. 跨平台比价。
4. 强医疗、强金融、强法律类商品推荐。
5. 完全个性化首页推荐流。

## 7. 核心流程

### 7.1 偏好沉淀

```text
用户咨询
  -> 系统推荐
  -> 用户点击关注 / 反馈偏好
  -> 系统写入偏好与关注记录
  -> 下次咨询优先复用
```

### 7.2 价格提醒

```text
用户关注商品
  -> 系统记录目标价或关注阈值
  -> 定时检查价格变化
  -> 命中条件时发送提醒
  -> 用户回到会话查看最新推荐
```

### 7.3 复访决策

```text
用户再次进入
  -> 系统展示上次总结
  -> 展示偏好与关注商品
  -> 用户继续追问或重新推荐
```

### 7.4 搭配购买

```text
用户选中商品
  -> 系统识别可搭配对象
  -> 输出单品 / 组合 / 替代方案
  -> 用户继续查看详情或加入关注
```

## 8. 页面建议

### 8.1 商品卡

新增：

1. 关注按钮。
2. 降价提醒入口。
3. 已关注状态。

### 8.2 会话页

新增：

1. 上次会话总结卡。
2. 我的偏好卡。
3. 关注商品卡。

### 8.3 商品详情页

新增：

1. 关注 / 取消关注。
2. 设定目标价。
3. 查看搭配购。

## 9. 验收口径

1. 用户可在桌面 Web 完成关注和取消关注。
2. 用户可查看并修改已保存偏好。
3. 价格命中后，能生成一条可追溯提醒。
4. 回访时能看到上次会话总结。
5. 关注和提醒不会打扰未授权用户。
6. 不影响一期导购、对比、反馈、会话等主链路。

## 10. 风险与控制

| 风险 | 说明 | 控制方式 |
| --- | --- | --- |
| 打扰过多 | 提醒频繁会让用户反感 | 默认低频提醒，用户可关闭 |
| 偏好失真 | 过度自动学习会写错偏好 | 以显式偏好为主，推断偏好可编辑 |
| 价格误报 | 价格源变化导致提醒不准 | 提醒记录保留价格时间戳与来源 |
| 体验分散 | 二期功能太多，主链路被稀释 | 先做 P0，P1/P2 分批上线 |
