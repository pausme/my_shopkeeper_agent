## 3. 本轮失败项

### F-REG-001 推荐结果品类一致性不足

| 项目 | 内容 |
| --- | --- |
| 严重级别 | P0 |
| 测试输入 | “预算500以内，想买空气炸锅，主要两个人用，希望容易清洗”，追问选择“好清洗” |
| 预期 | 推荐商品应优先且主要为“空气炸锅”；若同品类候选不足，应明确说明候选不足 |
| 实际 | 推荐卡出现破壁机、豆浆机等非目标商品 |
| 影响 | 用户会认为系统没有理解购买需求，直接影响推荐可信度 |
| 建议 | 在召回、排序、推荐生成三层增加目标品类约束；不足时用“候选不足”策略，不用相邻品类凑数 |
| 对应 TODO | `N11.25` |

### F-REG-002 推荐卡与对比表商品集合不一致

| 项目 | 内容 |
| --- | --- |
| 严重级别 | P0 |
| 预期 | 对比表只对本轮推荐商品做对比，且不排除目标商品 |
| 实际 | 推荐卡和对比表展示的商品集合不一致，对比表出现推荐卡外商品 |
| 影响 | 用户无法判断到底应该买哪个，且对比区会覆盖推荐主结论 |
| 建议 | 对比表只能消费当前推荐卡商品集合；默认不自动展开完整对比，用户主动选择后再生成 |
| 对应 TODO | `N11.26`、`N11.27` |

### F-REG-003 商品后端 ID 暴露需继续复核

| 项目 | 内容 |
| --- | --- |
| 严重级别 | P1 |
| 预期 | 面向用户的摘要、推荐理由、对比列头只展示商品名称，不展示后端 `product_id` |
| 实际 | 接口事件中仍包含 `product_id` 用于详情、反馈、对比等操作；本轮脚本检测到摘要或理由文本疑似包含后端 ID，需要进一步确认是否在前端可见 |
| 影响 | 若前端文案展示内部 ID，会破坏 C 端购物感知；若仅在接口结构字段中存在，则属于正常技术字段 |
| 建议 | 增加前端 DOM/E2E 断言：推荐卡标题、理由、对比列头、详情标题不得出现 `P0001` 这类后端 ID；接口字段可保留但不要进入用户文案 |
| 对应 TODO | 可并入 `N11.26`、`N11.28` 验收 |

### F-REG-004 PRD 停止会话接口未实现

| 项目 | 内容 |
| --- | --- |
| 严重级别 | P1 |
| PRD 接口 | `POST /api/shopping/sessions/{session_id}/stop` |
| 实际 | 线上请求返回 404 |
| 影响 | 前端“停止”目前更像浏览器侧中断请求，不是服务端会话终止；PRD、接口文档和实现不一致 |
| 建议 | 若产品保留“停止生成”能力，补服务端接口、会话状态更新和前端对接；若不做服务端终止，则从接口文档删除 |
| 对应 TODO | `M3.9` |

## 6. 建议修复顺序

1. P0：修复推荐品类一致性，保证“想买空气炸锅”不会推荐破壁机、豆浆机。
2. P0：修复推荐卡与对比表商品集合一致性，默认取消自动完整对比表。
3. P1：确认并修正后端 ID 是否进入用户可见文案，补前端 DOM 断言。
4. P1：补齐或删除 `POST /api/shopping/sessions/{session_id}/stop`。
5. P1：修复首页双输入线上回归和存量异常历史标题。
6. P2：补充发送中、失败恢复、历史删除确认、详情页下一步和键盘可访问性。

## 7. 回归测试沉淀建议

建议新增一个部署后回归脚本，覆盖以下断言：

| 类别 | 断言 |
| --- | --- |
| 认证 | 注册、登录、重复用户名、错误密码、限流 |
| 鉴权 | 未登录拒绝、JWT 通过、跨用户读写删除失败 |
| 导购 | 模糊需求追问、明确需求推荐、SSE 事件顺序、异常事件 |
| 推荐质量 | 目标品类一致、预算边界、推荐理由非空、不截断、不重复、不暴露后端 ID |
| 对比 | 手动对比成功、对比集合来自推荐集合、跨品类提示 |
| 会话 | 列表、详情回放、删除、删除后不可读 |
| 前端 | 首页单输入、推荐卡无 ID、对比列头无 ID、错误态可重试、弹窗键盘操作 |

该脚本应接入 `M8.6`，作为每次部署后必须跑的系统回归，而不是只跑单接口 smoke。

### 8.3 新观察到的产品取舍

| 观察点 | 影响 | 建议 |
| --- | --- | --- |
| 空气炸锅同品型候选只有 1 款时，系统现在只推荐 1 款并提示“同品类候选不足” | 解决了跨品型凑数问题，但与“完整需求至少 3 个推荐商品”的旧验收口径冲突 | 调整验收规则：具体品型候选不足时，允许少于 3 款，但必须明确说明候选数量和不凑数原因 |
| `persist_and_emit` 仍无条件发送 `comparison` 事件 | 目前集合一致，但产品层面的“N11.27 不主动自动对比”仍未完成 | 若保留自动对比，需前端降级展示；若坚持用户主动对比，应后端按 intent/selected_product_ids 控制是否发送 comparison |
| 首页底部对话 `textarea` 未再复现 | `N11.14` 主问题基本解除 | 仍需补 E2E 断言：首页状态下不得出现对话输入栏 |
| 历史/设置浮层可同时保持打开 | 页面会同时出现历史搜索框、访问令牌输入框和首页搜索框 | 设置、历史应互斥打开；打开一个浮层时关闭另一个 |
| 最近咨询仍出现标题 `1` | 存量异常会话标题仍影响历史识别 | `N11.15` 仍需数据迁移或后台修复脚本 |

### 8.4 当前结论

本轮技术修复对 P0 主链路有效：推荐品类一致性和推荐/对比集合一致性已通过线上主用例复测。仍不建议直接关闭所有相关 TODO，原因是自动化回归套件尚未沉淀，停止会话接口仍缺失，自动对比策略与历史标题治理还未完全闭环。
