## 2. 产品定位

AI 商品决策助手是一款面向电商用户的智能导购工具。用户可以用自然语言描述真实购买需求，系统基于商品属性、价格、库存、销量、评分、评价内容、优惠信息和售后风险，输出可解释的商品推荐、商品对比、买前避坑和多轮追问建议。

一句话定位：

> 帮用户把“我该买哪个”变成一个可解释、可比较、可行动的购买决策。

## 3. 背景与机会

在 C 端电商场景中，搜索和推荐已经能解决“找到商品”的问题，但还没有很好解决“买哪个更适合我”的问题。尤其在家电、数码、母婴、家居、厨房小电器等中高决策成本品类中，用户常常面临信息过载、关键词搜索理解有限、商品对比成本高、推荐缺少解释、买错后退货成本高等问题。

AI 导购具备明确的实际价值，但用户信任需要通过“可解释、可验证、少打扰”的体验建立。公开行业资料显示，AI shopping assistant 的认知在提升，但用户仍需要更强的帮助感；同时，买前决策质量直接影响转化和售后成本。NRF 2025 年退货报告预计 2025 年线上销售退货率为 19.3%，说明买错商品的成本是真实存在的。

## 4. 产品目标

### 4.1 用户目标

1. 用户可以用自然语言表达需求，不需要先理解复杂商品参数。
2. 用户可以快速获得 3-5 个可信商品推荐。
3. 用户可以看到推荐理由、风险提示、适合人群和不适合情况。
4. 用户可以通过多轮追问继续收窄条件。
5. 用户可以在一个页面完成商品理解、比较和决策。

### 4.2 业务目标

1. 提升从搜索/导购入口到商品点击的转化率。
2. 提升推荐商品加购率。
3. 降低用户决策时长。
4. 降低因“不符合预期”导致的退货率。
5. 沉淀用户真实需求表达，反哺商品运营、搜索和推荐策略。

### 4.3 技术目标

1. 复用当前项目的 LangGraph 工作流能力，完成可观测、可扩展的 AI 导购链路。
2. 复用 Qdrant 和 Elasticsearch，分别支撑商品语义召回和评价/属性全文检索。
3. 复用 FastAPI SSE 能力，实现逐步流式反馈。
4. 将 SQL 查询能力从“商家问数”调整为“用户商品决策数据查询”。

## 5. 目标用户

| 用户类型 | 特征 | 核心诉求 |
| --- | --- | --- |
| 新手购买用户 | 对品类不了解 | 想知道怎么选、避开什么坑 |
| 场景型用户 | 有明确使用场景 | 希望系统按场景推荐 |
| 对比纠结用户 | 收藏多个商品 | 希望快速比较优缺点 |
| 价格敏感用户 | 有预算上限 | 希望在预算内找到最优选择 |
| 低耐心用户 | 不愿读长详情和评论 | 希望系统直接给结论和依据 |

### 首期品类建议

厨房小电器、家居生活、数码配件、母婴用品。

### 不建议首期覆盖

服饰全品类、美妆功效类、医疗健康类、大家电安装全流程。

## 6. 核心场景

1. 用户会描述需求但不会选参数。
2. 用户在多个商品之间纠结。
3. 用户在预算约束下找最优解。
4. 用户想买前避坑。
5. 用户发起多轮追问继续筛选。

## 7. 功能范围

### 7.1 一期 MVP

| 模块 | 功能 |
| --- | --- |
| 自然语言输入 | 接收购买需求、比较、避坑问题 |
| 意图识别 | 识别推荐、对比、摘要、追问、筛选条件修改 |
| 槽位抽取 | 抽取品类、预算、场景、人群、品牌、偏好、排除项 |
| 智能追问 | 信息不足时追问 1-2 个关键问题 |
| 商品召回 | 基于商品标题、类目、属性、评价关键词召回 |
| 商品重排 | 综合需求匹配、价格、评分、销量、风险、库存排序 |
| 推荐解释 | 输出推荐理由、适合人群、不适合情况、风险提示 |
| 商品对比 | 以表格展示候选商品核心差异 |
| SSE 流式反馈 | 展示理解、召回、分析、推荐步骤 |
| 结果反馈 | 记录推荐是否有帮助 |

### 7.2 二期范围

价格监控与降价提醒、用户偏好记忆、图文评价摘要、搭配购买方案、购物车和优惠券计算、已购商品联动推荐。

### 7.3 暂不做

跨平台比价、自动下单、强医疗/金融/法律属性商品推荐、完全个性化首页推荐流、商家广告投放后台。

## 8. 用户流程

```text
进入 AI 导购入口
  -> 输入自然语言需求
  -> 系统识别意图和槽位
  -> 判断信息是否足够
  -> 不足则追问
  -> 召回候选商品
  -> 分析商品属性和评价
  -> 重排候选商品
  -> 生成推荐结果
  -> 用户点击 / 继续追问 / 反馈
```

## 9. 页面设计

### 9.1 AI 导购首页

自然语言输入框、场景快捷入口、历史咨询记录、热门问题推荐。

### 9.2 对话推荐页

用户问题气泡、系统追问气泡、推荐商品卡片、推荐理由、风险提示、商品对比表、继续追问输入框、反馈入口。

### 9.3 商品对比页

价格、核心参数、需求匹配度、评分与销量、好评关键词、差评关键词、适合人群、不适合情况、推荐结论。

## 10. 核心功能需求

### 10.1 自然语言理解

系统需要识别意图、品类、预算、使用人群、使用场景、偏好、排除条件、商品范围。

### 10.2 智能追问

最多连续追问 2 次，每次只问 1 个最关键问题，允许用户跳过。

### 10.3 商品召回

召回数据源包括商品标题、类目、属性、详情文本、评价、历史购买和点击数据。

### 10.4 商品排序

推荐按需求匹配度、价格竞争力、评价质量、销量与热度、售后风险、平台策略综合排序。

### 10.5 推荐结果生成

推荐结果必须包含结论、商品列表、推荐理由、风险提示、适合人群、不适合情况、对比表、下一步建议。

### 10.6 商品对比

支持至少 3 个商品横向对比，若跨品类需要明确提示不适合直接比较。

### 10.7 评价摘要与避坑

提取正向/负向高频评价、质量问题、适配问题、噪音/气味/耐用性问题、物流和售后问题。

### 10.8 多轮追问

支持“有没有更便宜的”“只看自营”“不要白色”“帮我比较前两个”等上下文追问。

## 11. 数据需求

### 11.1 商品基础数据

商品 ID、标题、类目、品牌、价格、优惠价、库存、销量、评分、评论数、属性、详情文本、主图、状态。

### 11.2 评价数据

评价 ID、商品 ID、评分、评价内容、追评、规格信息、情感倾向、评价标签、时间。

### 11.3 经营与行为数据

点击率、加购率、转化率、退货率、售后率、优惠信息、履约信息、用户搜索词、点击、收藏、购买、反馈。

## 13. 非功能需求

1. 首个 SSE 进度事件返回时间不超过 1 秒。
2. 无缓存时首屏推荐结果目标不超过 8 秒。
3. 允许外部检索失败时降级。
4. 查询失败必须返回用户可理解的错误信息。
5. 不输出 SQL、提示词、内部权重和堆栈。
6. 评价样本不足时必须提示。

## 14. 成功指标

| 指标 | 目标 |
| --- | --- |
| AI 导购入口点击率 | >= 8% |
| 对话完成率 | >= 60% |
| 推荐商品点击率 | >= 35% |
| 推荐后加购率 | >= 12% |
| 追问率 | >= 20% |
| 有帮助反馈率 | >= 60% |
| 无结果率 | <= 8% |
| 推荐失败率 | <= 3% |

## 15. 验收标准

1. 完整需求下至少返回 3 个推荐商品。
2. 每个商品必须包含推荐理由和风险提示。
3. 商品对比至少支持 3 个商品。
4. 多轮追问必须继承上下文。
5. 无结果时必须说明原因并给出放宽条件建议。
6. 不编造商品参数和评价内容。

## 16. MVP 排期

| 阶段 | 周期 | 交付内容 |
| --- | --- | --- |
| 需求与数据设计 | 第 1 周 | 首期品类、字段、结果结构 |
| 核心链路开发 | 第 2 周 | 意图识别、槽位抽取、召回、过滤 |
| 推荐与解释 | 第 3 周 | 重排、推荐理由、风险提示 |
| 前端体验 | 第 4 周 | 对话页、卡片、对比表 |
| 反馈与埋点 | 第 5 周 | 用户反馈、埋点、错误监控 |
| 灰度与调优 | 第 6 周 | 灰度测试、真实 query 调优 |

## 17. 与当前项目的改造关系

当前项目可复用 FastAPI、SSE、LangGraph、Qdrant、Elasticsearch、MySQL、React 前端和依赖注入。改造重点是把“问数”切换成“导购”，把字段/指标召回切换成商品/评价/风险召回，把 SQL 生成切换成推荐结果生成。
