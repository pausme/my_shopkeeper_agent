# 二期需求开发文档：AI 商品决策助手

## 1. 文档目标

本文档用于指导二期开发落地，聚焦三件事：

1. 把二期 PRD 拆成可开发任务。
2. 把接口、数据表、Agent、前端和测试串起来。
3. 让一期已完成的导购链路继续稳定运行。

## 2. 二期开发原则

1. 优先复用现有会话、推荐、反馈、埋点能力。
2. 偏好和提醒必须可查询、可编辑、可删除。
3. 所有用户可见文案不展示内部 ID。
4. 二期仍然只做桌面 Web，不做移动端适配。
5. 新能力必须有回归测试，不影响一期主链路。

## 3. 二期模块拆分

### 3.1 模块 A：偏好中心

目标：把用户在导购过程中的显式偏好沉淀为可控画像。

能力清单：

1. 保存偏好。
2. 查看偏好。
3. 编辑偏好。
4. 删除偏好。
5. 记录偏好来源：显式 / 推断。

### 3.2 模块 B：商品关注与降价提醒

目标：让用户对某个商品建立长期关注关系。

能力清单：

1. 关注商品。
2. 设置目标价。
3. 取消关注。
4. 命中提醒后生成可追溯记录。
5. 支持用户在会话里查看关注状态。

### 3.3 模块 C：会话总结与复访

目标：让用户回访时不用重读整段历史。

能力清单：

1. 生成历史会话摘要。
2. 提取未决问题。
3. 提取关注商品。
4. 支持“继续追问上次问题”。

### 3.4 模块 D：搭配购买与已购联动

目标：在单品推荐之外提供组合方案。

能力清单：

1. 根据当前商品输出搭配建议。
2. 根据已购商品避免重复推荐。
3. 给出补充购或替代购建议。

### 3.5 模块 E：运营支撑

目标：给运营和商品维护提供基础工具。

能力清单：

1. 商品摘要编辑。
2. 风险摘要编辑。
3. 提醒规则配置。
4. 数据重建与刷新。

## 5. 数据表设计

### 5.1 复用表

1. `shopping_user_preference`：已有偏好表，承载用户偏好画像。
2. `shopping_event_log`：已有埋点表，承载关注、提醒、点击、回访事件。
3. `shopping_session`：已有会话表，承载会话摘要和复访入口。

### 5.2 建议新增表

#### 5.2.1 商品关注表 `shopping_watchlist`

| 字段 | 说明 |
| --- | --- |
| watch_id | 关注记录 ID |
| user_id | 用户 ID |
| product_id | 商品 ID |
| product_title_snapshot | 商品标题快照 |
| target_price | 目标价 |
| current_price | 当前价 |
| status | active / triggered / canceled |
| created_at | 创建时间 |
| updated_at | 更新时间 |

#### 5.2.2 价格提醒表 `shopping_price_alert`

| 字段 | 说明 |
| --- | --- |
| alert_id | 提醒 ID |
| watch_id | 关联关注记录 |
| user_id | 用户 ID |
| product_id | 商品 ID |
| alert_price | 命中价格 |
| alert_reason | 命中原因 |
| alert_status | pending / sent / read |
| created_at | 创建时间 |

#### 5.2.3 会话摘要表 `shopping_session_summary`

| 字段 | 说明 |
| --- | --- |
| summary_id | 摘要 ID |
| session_id | 会话 ID |
| user_id | 用户 ID |
| summary_text | 会话摘要 |
| unresolved_questions_json | 未决问题 |
| focus_products_json | 关注商品 |
| created_at | 创建时间 |

### 5.3 表设计要求

1. 业务 ID 继续统一使用 `varchar(64)`。
2. 二期新增表必须带 `user_id`，避免跨用户串读。
3. 提醒与关注必须保留时间戳，便于追踪。
4. 摘要和偏好都必须可重建，不依赖一次性结果。

## 8. 开发排期建议

### Sprint 1：偏好中心 + 会话摘要

| 任务 | 内容 | 依赖 | 验收 |
| --- | --- | --- | --- |
| S1-1 | 新增/完善 `shopping_user_preference` 的读写接口 | 现有用户鉴权、会话上下文 | 可保存、查询、修改、删除单条偏好 |
| S1-2 | 抽取偏好信号节点 `extract_preference_signals` | 一期导购对话流 | 推荐后能写入显式偏好或推断偏好 |
| S1-3 | 会话总结节点 `build_session_summary` | `shopping_session`、`shopping_message` | 可生成一段可读总结和未决问题 |
| S1-4 | 前端偏好卡展示 | 现有会话页 | 能看到偏好列表和来源标记 |
| S1-5 | 前端会话总结卡 | 现有历史会话页 | 回访历史会话时展示摘要、未决问题、继续追问入口 |

交付定义：

1. 偏好能被用户主动增删改查。
2. 会话总结能给出一段可读文本，不要求一次很长，但必须可复访。
3. 不影响一期推荐、对比、反馈、会话接口。

### Sprint 2：商品关注 + 降价提醒

| 任务 | 内容 | 依赖 | 验收 |
| --- | --- | --- | --- |
| S2-1 | 新增 `shopping_watchlist` 表 | 商品主数据、用户鉴权 | 用户可关注/取消关注商品 |
| S2-2 | 新增 `shopping_price_alert` 表 | `shopping_watchlist` | 命中提醒后有可追溯记录 |
| S2-3 | 关注/取消关注接口 | 商品详情页、商品卡 | 单个商品关注状态可切换且幂等 |
| S2-4 | 定时价格检查任务 | 商品价格源、关注列表 | 命中目标价时生成提醒 |
| S2-5 | 前端关注状态和提醒列表 | 商品卡、会话页 | 可看到已关注状态、目标价、最近提醒 |

交付定义：

1. 关注和取消关注必须是幂等的。
2. 提醒记录必须能回查来源商品和触发价格。
3. 用户能主动关闭提醒，不被动打扰。

### Sprint 3：搭配购买 + 已购联动 + 运营支撑

| 任务 | 内容 | 依赖 | 验收 |
| --- | --- | --- | --- |
| S3-1 | 搭配购买接口 `/api/shopping/bundles/recommend` | 商品标签、评价摘要、风险摘要 | 输出组合购/补充购建议 |
| S3-2 | 已购联动规则 | 已购商品数据源 | 已购商品不重复推荐，能提示替代或升级方案 |
| S3-3 | 购物车模拟接口 `/api/shopping/cart/simulate` | 价格、优惠券、组合规则 | 可计算组合价格与优惠效果 |
| S3-4 | 商品摘要/风险摘要后台可编辑 | 运营支撑入口、商品主数据 | 运营可修正摘要并立即生效 |
| S3-5 | 前端搭配方案展示 | 商品详情页、会话页 | 用户可直接看到单品/组合/替代方案 |

交付定义：

1. 搭配方案默认是辅助信息，不覆盖主推荐。
2. 已购联动必须避免重复推荐。
3. 运营改动摘要后，前端能在下次拉取时看到生效结果。

### 里程碑建议

1. Sprint 1 先把“记住用户”做出来。
2. Sprint 2 再把“提醒用户”做出来。
3. Sprint 3 最后把“扩展推荐”做出来。
4. 每个 Sprint 必须保留一期主链路回归，不允许回退推荐、对比、反馈、会话。

## 9. 验收与测试

### 9.1 必测项

1. 偏好新增、修改、删除。
2. 商品关注、取消关注、重复关注。
3. 降价提醒命中与已读状态。
4. 会话摘要生成与复访展示。
5. 搭配购买返回可读结果。

### 9.2 回归项

1. 一期推荐不回退。
2. 一期对比不回退。
3. 用户可见文案不出现内部 ID。
4. 历史会话切换不串状态。

## 10. 风险点

| 风险 | 说明 | 控制方式 |
| --- | --- | --- |
| 提醒过密 | 用户收到太多提醒 | 限频、静默期、可关闭 |
| 偏好误写 | 自动抽取偏好不准 | 显式偏好优先，可编辑 |
| 摘要漂移 | 会话总结不完整 | 摘要可重建，保存原会话消息 |
| 组合过度推荐 | 搭配购影响主结论 | 搭配方案默认降级为次操作 |
