| 项目 | 内容 |

## 2. 改版结论

### 2.1 产品定位

PickMate AI 不是单纯的聊天机器人，也不是商品瀑布流，而是一个帮助用户做购买判断的决策工具。

用户需要在一个连续工作区内完成：

1. 描述购买需求。
2. 补充预算、场景、偏好和排除项。
3. 查看候选商品及推荐理由。
4. 核对评价、风险、样本量和更新时间。
5. 选择 2~4 款商品进行对比。
6. 回访历史会话并继续决策。

### 2.2 视觉气质

采用“安静可靠、信息清楚、决策优先”的视觉方向：

- Energy：中低能量。用户要快速扫描和比较，不需要强装饰。
- Finish：精细、干净。使用清晰边框、少量阴影和稳定对齐。
- Density：标准偏密。推荐信息要有足够密度，但不压迫阅读。
- Weight：中等偏重。价格、结论和风险需要明显层级。
- Seriousness：偏认真，但保留消费场景的轻松感。

以上判断来自产品的核心任务：价格、评分、评价和风险都属于需要核对的事实信息，视觉表达必须服务可信度和决策速度。

### 2.3 设计原则

1. **结论先行**：先让用户知道推荐结论，再展开商品事实。
2. **证据可见**：评价样本、更新时间、风险和数据性质不能藏在深层页面。
3. **一个主动作**：每个区域只突出一个下一步动作。
4. **空间有连续性**：从推荐卡打开详情、从详情进入对比或搭配购时，保持当前会话上下文。
5. **技术细节不打扰普通用户**：访问令牌、后端 ID、SQL、调试信息不出现在 C 端主界面。
6. **桌面优先但不写死宽度**：支持 1024、1280、1440、1920 宽度，不出现横向滚动和内容遮挡。

## 3. 当前问题与本期解决范围

### 3.1 当前主要问题

1. 首页、对话页、管理台虽然能用，但视觉语言不统一。
2. 首页偏“AI 工具入口”，缺少“正在做购买决策”的场景感。
3. 推荐卡信息完整，但价格、推荐结论、风险和 CTA 的优先级还不够明确。
4. 商品详情使用中心弹窗，容易打断当前对话上下文。
5. 对比表偏后台数据表，缺少“哪款更适合我”的结论层。
6. 当前条件、偏好、对比商品、历史会话分散在不同位置，用户需要来回寻找。
7. 管理台的视觉和导购端割裂，返回导购还存在上下文丢失问题。

### 3.2 本期必须同步关注的功能问题

以下问题不是纯视觉问题，但会直接影响改版验收：

- `N11.32`：显式品型无结果时不得推荐相邻品类。
- `N11.33`：显式对比提交后不得回到首页，必须保留会话并展示对比结果。
- `N11.34`：管理台返回导购时恢复进入前的页面和会话上下文。

## 4. 视觉设计系统

### 4.1 色彩 Token

采用浅色工作区，主色使用深桉树绿，价格使用暖红橙，风险使用语义红，避免整站泛蓝或紫色 AI 风格。

| Token | Hex | 用途 |
| --- | --- | --- |
| `ui-bg` | `#F3F6F4` | 页面背景、工作区底色 |
| `ui-surface` | `#FFFFFF` | 卡片、抽屉、输入区 |
| `ui-surface-subtle` | `#EAF0EC` | 次级区域、筛选区、条件区 |
| `ui-surface-warm` | `#FFF9F3` | 价格提示、预算相关说明 |
| `ui-primary` | `#1F5D4B` | 主按钮、选中态、重点链接 |
| `ui-primary-hover` | `#17483A` | 主按钮 hover/active |
| `ui-primary-soft` | `#E1F0EA` | 主色浅底、导航选中背景 |
| `ui-price` | `#B84A27` | 到手价、优惠金额、价格标签 |
| `ui-warning` | `#A96B14` | 样本不足、略超预算、待确认 |
| `ui-error` | `#B42318` | 错误、阻断、删除 |
| `ui-success` | `#1F7A4D` | 成功、已购、已关注 |
| `ui-text` | `#18221F` | 标题、正文 |
| `ui-text-secondary` | `#53635C` | 辅助说明、次级信息 |
| `ui-text-muted` | `#718078` | 时间、标签、弱提示 |
| `ui-border` | `#D7E0DB` | 卡片边框、分割线 |
| `ui-focus` | `#2F8F72` | 键盘焦点环 |

色彩使用比例：

- 约 65%：`ui-bg`、`ui-surface` 和低饱和中性色。
- 约 25%：`ui-surface-subtle`、`ui-primary-soft`、`ui-surface-warm`。
- 约 10%：`ui-primary`、`ui-price`、语义状态色。

禁止：

- 紫蓝渐变、粉青渐变、彩虹渐变。
- 深色背景 + 霓虹边框。
- 大面积主色铺底。
- 通过颜色单独表达成功、风险或选中状态，必须同时有文字或图标。

### 4.2 字体

| 用途 | 建议 |
| --- | --- |
| 中文主字体 | 从 `emfont-fonts` 选择 1 个中性中文字体；候选可使用 `ChironHeiHK`，系统回退 `PingFang SC`、`Microsoft YaHei` |
| 拉丁及数字 | `IBM Plex Sans`，从 Google Fonts 加载，系统回退 `Arial` |
| 代码/调试信息 | 仅高级设置或管理台必要位置使用等宽字体 |

字号：

| Token | 尺寸 | 行高 | 用途 |
| --- | --- | --- | --- |
| `display` | 40px | 1.15 | 首页主标题，仅首页使用 |
| `page-title` | 28px | 1.25 | 管理台标题、对比页标题 |
| `section-title` | 18px | 1.35 | 推荐区、证据区、历史区 |
| `body` | 15px | 1.65 | 对话正文、推荐理由 |
| `body-small` | 14px | 1.55 | 表格内容、详情内容 |
| `caption` | 12px | 1.45 | 时间、数据来源、辅助说明 |
| `label` | 11px | 1.35 | 标签、状态、分组标题 |

要求：

- 正文不得小于 14px。
- 价格、评分、销量、样本量使用 `tabular-nums`。
- 不使用负字距，中文正文保持 `letter-spacing: 0`。
- 首屏最多出现标题、正文、标签三类主要文字层级。

### 4.3 间距、圆角、阴影

基础间距使用 8px：

```text
4 / 8 / 12 / 16 / 24 / 32 / 40 / 48 / 64
```

| 元素 | 规范 |
| --- | --- |
| 按钮高度 | 36px 普通按钮，40px 主按钮 |
| 图标按钮点击区域 | 不小于 40×40px |
| 卡片圆角 | 10px |
| 抽屉圆角 | 左侧上/下角 12px |
| 输入框圆角 | 10px |
| 标签圆角 | 999px 或 6px，按标签语义选择 |
| 卡片内边距 | 20px；紧凑表格区域 16px |
| 卡片阴影 | `0 1px 3px rgba(24,34,31,0.08)` |
| 抽屉阴影 | `-12px 0 32px rgba(24,34,31,0.16)` |
| 浮层阴影 | `0 12px 32px rgba(24,34,31,0.16)` |

不要在卡片内继续嵌套一层同等级卡片。分组优先使用背景色、分割线和间距完成。

## 5. 页面与信息架构

## 5.1 应用 Shell

保留顶部导航，但改成“工作区导航”：

```text
品牌区 | 首页 | 当前会话 | 历史                         设置 / 登录
```

要求：

- 当前页面使用 `ui-primary-soft` 背景 + `ui-primary` 文字 + 字重变化。
- 顶部高度 56px，底部 1px 分割线。
- Logo 使用单色购物决策符号，不使用渐变、发光或装饰星星。
- `当前会话` 无会话时隐藏，已有会话时显示。
- 管理台入口保留在设置中，普通用户不在主导航中看到技术配置。
- 管理台入口必须带来源上下文，修复 `N11.34`。

## 5.2 首页：决策输入台

首页不做营销 Landing Page，直接进入可用的购买决策输入。

12 栏布局：

- 左侧 7 栏：主输入和新手提示。
- 右侧 5 栏：最近决策、热门问题和场景入口。
- 1024px 以下改为单列，右侧内容下移。

页面结构：

1. 页面标题：`买什么，先把条件说清楚`。
2. 副标题：说明系统会分析价格、评价、风险和适配度。
3. 主输入框：大输入区，支持 Enter 提交，保留 500 字限制。
4. 条件提示：预算、场景、偏好、排除项四个输入提示。
5. 场景入口：租房、送礼、母婴、厨房、数码、收纳。
6. 最近会话：最多展示 3 条，标题必须经过现有治理函数处理。
7. 热门问题：采用紧凑列表，不使用大面积重复卡片。

首页主输入要求：

- 输入框高度不少于 88px，聚焦时显示 `ui-focus` 外环。
- “问导购”为唯一主按钮。
- 空输入时按钮禁用并有清晰 disabled 状态。
- 发送中时输入区、场景入口、热门问题均不可重复提交。
- 不再同时展示首页底部 composer。

## 5.3 对话页：三段式决策工作区

桌面端使用 12 栏布局：

```text
左侧 7 栏：对话流
右侧 5 栏：决策侧栏
```

### 左侧对话流

- 用户问题显示为轻量右对齐气泡，不使用大面积实心主色。
- AI 内容使用白色内容面，左侧显示统一助手标识。
- 流式进度使用步骤条和明确用户文案：
  - 理解你的需求
  - 筛选候选商品
  - 分析评价与风险
  - 综合比较候选
  - 整理推荐理由
- 过程区域不展示技术节点名、SQL、模型信息或调试堆栈。
- 推荐结果和对比表保持在当前会话流内，不能跳回首页。

### 右侧决策侧栏

固定在对话页右侧，宽度建议 320~380px：

1. 当前条件：品类、预算、场景、排除项。
2. 我的偏好：显式偏好、推断偏好，支持删除。
3. 对比托盘：已选商品、移除、开始对比。
4. 当前会话操作：停止、重新生成、新咨询。

侧栏要求：

- 侧栏滚动和对话流滚动互不影响。
- 对比商品名称使用 `truncate`，悬停显示完整名称。
- 对比数量显示为 `0/4`、`1/4`、`2/4` 等，不允许超过 4 个。
- 对比未满 2 个时，开始对比按钮禁用且保留说明。
- 对比提交失败时，在当前会话显示错误卡和重试入口。

### 底部 composer

- 仅对话页显示。
- 输入框和发送按钮合并为一个固定工作区。
- 对比托盘放在 composer 上方，不再被悬浮“新咨询”按钮遮挡。
- 有对比商品时隐藏或让位给悬浮操作，确保开始对比可点击。
- 停止按钮只在流式请求期间显示。

## 5.4 推荐商品卡

推荐卡改成“决策卡”，信息顺序固定：

```text
推荐结论
商品图片 + 商品名称
到手价 + 原价 + 优惠
评分 + 月销 + 数据性质
匹配理由
风险提示
主操作：查看详情
次操作：加入对比 / 继续追问 / 关注 / 反馈
```

规范：

- 商品图片区域建议 112×112px，必须显示真实商品图片或可信商品渲染图。
- 无图片时使用与品类相关的稳定 fallback，并标注演示数据，不使用灰色空框。
- 到手价使用 `ui-price`，字号 22px，数字使用 `tabular-nums`。
- “最推荐 / 预算优先 / 品质优先 / 谨慎购买”使用状态标签，状态必须同时体现文字。
- 推荐理由最多 3 条，每条完整成句，不重复风险标签。
- 风险标签最多 2 个，使用图标 + 文字，不仅依赖红色。
- “查看详情”为唯一实心主按钮。
- “加入对比”为描边次按钮。
- “继续追问”和“反馈”为低权重文字按钮。
- 商品卡禁止展示 `P0001` 等后端 ID。

## 5.5 商品详情：右侧证据抽屉

将中心弹窗改为右侧证据抽屉，保持当前对话可见。

抽屉结构：

1. 顶部：商品图、名称、品牌、评分、到手价。
2. 可信信息：演示数据、样本量、更新时间、价格来源。
3. 核心参数：两列或三列网格。
4. 评价摘要：好评关键词、差评关键词、风险等级。
5. 适合 / 不适合人群。
6. 底部固定操作区：
   - 加入对比
   - 继续追问这款
   - 复制商品名称
   - 查看搭配购
   - 标记为已购

交互要求：

- Esc、遮罩点击、关闭按钮都可关闭。
- 打开抽屉后焦点进入标题或关闭按钮。
- Tab 顺序只在抽屉内循环，关闭后焦点回到触发按钮。
- 详情数据加载、失败、空参数、低样本均有独立状态。
- 标记已购后按钮立即变为“已购（点击撤销）”，刷新后状态保留。

## 5.6 商品对比页/对比区域

对比区域使用“结论 + 表格 + 建议”结构：

1. 顶部结论：一句话说明更适合谁。
2. 商品列头：商品图、商品名、到手价、推荐结论。
3. 关键维度：价格、评分、核心参数、评价、风险、适合人群。
4. 最低价、最高评分、最高风险使用颜色 + 文字说明高亮。
5. 底部保守购买建议。
6. CSV 导出保留，按钮带下载图标。

对比规则：

- 只展示用户显式选择或当前对比请求指定的商品。
- 支持 2、3、4 款商品。
- 选中商品必须保持用户选择顺序。
- 显式对比不应被普通品类过滤、语义地板、预算过滤或风险过滤误剔除。
- 对比失败必须留在当前会话，不得返回首页。
- 跨品类对比必须显示清晰风险提示。

## 5.7 历史会话与总结

历史入口继续使用点击展开：

- 展开层宽度 320px 左右。
- 每条记录显示标题、最近问题、时间。
- 加载中显示行级状态，删除保留二次确认。
- 从历史进入会话后恢复总结卡、消息、推荐卡和对比表。
- 总结卡只展示商品名称，不展示商品 ID。
- 管理台返回导购时，按 `N11.34` 恢复原会话。

## 5.8 管理台

管理台采用同一套颜色、字体、边框和按钮 Token，但密度可以更高：

- 页面背景、导航、表格、抽屉与导购端统一。
- 标题区使用“商品数据管理台 + 返回导购”。
- 返回导购使用来源上下文，不固定跳转 `#/`。
- 商品 ID 只在管理台表格显示，不能泄漏到 C 端商品卡、总结卡、对比表和推荐理由。
- 表格行操作使用图标 + 明确 aria-label。
- 编辑、评价、风险摘要使用右侧抽屉。
- 删除、重建索引、规则保存均要有 loading、success、error 状态。

## 7. 交互状态要求

所有新增或改造的按钮、输入框、卡片和抽屉按以下状态实现：

| 状态 | 要求 |
| --- | --- |
| Default | 层级清晰，文字和边界可读 |
| Hover | 提升边界或阴影，不改变布局尺寸 |
| Focus | `focus-visible` 至少 2px 焦点环，不能只靠颜色 |
| Active | `active:scale-[0.98]` 或等效按压反馈 |
| Disabled | 透明度 50%~60%，禁用光标，不可点击 |
| Loading | 显示具体动作，例如“正在加载评价摘要”，禁止只写“Loading” |
| Success | 文字 + 图标说明成功，2~3 秒后可消失 |
| Error | 说明发生了什么、原因以及用户下一步怎么做 |

错误文案示例：

- 对比提交失败：`对比暂时没有完成，当前会话还在。请重试，或先移除一款商品后再试。`
- 详情加载失败：`商品详情暂时加载失败，推荐卡中的信息仍可查看。重新加载`
- 无匹配商品：`暂时没有找到“蓝牙耳机”商品。可以换一个型号，或确认是否要扩大到数码配件。`
- 管理台无权限：`你没有商品数据管理权限，请切换管理员账号后再进入。`

## 8. 动效要求

本产品是决策工具，动效只服务于反馈、引导和连续性：

- 按钮按下：50~100ms，`scale 0.98`。
- 抽屉打开：从右侧 16px 进入，180~240ms，ease-out。
- 抽屉关闭：向右退出，140~180ms，ease-in。
- 推荐卡加载：使用与最终卡片结构一致的 skeleton，不使用全屏旋转 loading。
- 流式步骤：当前步骤高亮，完成后静态保留。
- 不使用滚动劫持、鼠标跟随、持续漂浮、自动轮播和装饰性入场动画。
- `prefers-reduced-motion: reduce` 时关闭位移和 shimmer，保留内容和状态变化。

## 9. 响应式和可访问性

### 9.1 视口验收

必须实测：

- 1024×768
- 1280×800
- 1440×900
- 1920×1080

验收项目：

- 页面无横向滚动。
- 对比表可以横向滚动，但表格外层不撑破页面。
- 商品名、推荐理由和 CTA 不出现竖排或重叠。
- 右侧决策栏不会遮挡 composer 和对比托盘。
- 详情抽屉和搭配购抽屉不会遮挡关闭按钮。

### 9.2 可访问性

- 正文文字不低于 14px。
- 普通文字对比度不低于 4.5:1。
- 所有图标按钮有 `aria-label` 或可读文本。
- 图片有准确 alt 文本，失败时不出现空白破图。
- 键盘可以访问：首页输入、提交、历史、详情、对比、抽屉关闭。
- 抽屉打开时支持 Esc，关闭后焦点返回触发元素。
- 风险、成功、已购、已关注不能只用颜色表达。

## 11. 验收标准

### 11.1 核心流程

- 首页只有一个主搜索入口。
- 输入购买需求后，可以正常完成追问和推荐。
- 推荐卡首屏可看到商品图片、到手价、推荐结论、推荐理由和主 CTA。
- 点击查看详情后打开证据抽屉，不丢失当前会话。
- 选择 2~4 款商品后，点击开始对比，仍停留在当前会话并生成对比表。
- 对比表展示的商品与用户选择完全一致，顺序一致。
- 点击搭配购可以看到组合购、补充购或明确空状态。
- 标记已购后，搭配购不再重复推荐该商品，刷新后状态仍保留。
- 历史回访可以恢复总结、消息和推荐内容。
- 从管理台返回时恢复原导购页或原导购会话。

### 11.2 信任与信息安全

- C 端不出现 `P0001`、`product_id`、SQL、提示词和调试堆栈。
- 商品图片、价格、评分、销量、样本量和更新时间的展示层级清晰。
- 演示数据必须有统一标识。
- 价格、评价和风险来源不能被视觉装饰遮挡。

### 11.3 工程验收

- `pnpm build` 通过。
- 现有 `pytest` 通过。
- 现有导购接口冒烟和回归脚本通过。
- Playwright 覆盖首页、推荐卡、详情抽屉、对比流程、历史回访、管理台返回。
- 四个桌面宽度截图无横向溢出、文字重叠和按钮遮挡。
- `prefers-reduced-motion` 下页面仍可完成全部操作。
